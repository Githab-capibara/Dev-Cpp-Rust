# 08. Compile & Run: программа стримит вывод через тот же пайплайн

- **Status:** Accepted
- **Date:** 2026-11-24
- **Deciders:** @Githab-capibara
- **Related:** [04. Makefile-пайплайн](04-makefile-pipeline.md)

## Context

Первая реализация «Compile and Run» в GUI запускала джоб сборки, но не
сохраняла его в состоянии — поллер сразу получал `None`, и действие молча
ничего не делало (баг найден при разборе работы предыдущей сессии). Плюс
отдельный запуск процесса в обход пайплайна показывал вывод программы только
в статус-баре, а не в Compiler Output, как в Dev-C++.

## Decision

**`RunMode::BuildAndRun` исполняется внутри build-джоба:** после успешного
`make` фоновый поток сам запускает исполняемый файл с piped stdout/stderr и
отправляет его строки как `BuildMessage::Line` (фаза `Phase(Running)`).
GUI просто рисует лог; статус «Running…» ставится по фазе. Неуспешный код
возврата программы даёт `Finished(false)`.

## Consequences

- **Easier:** один путь вывода для компилятора и программы; поведение как в
  Dev-C++; код GUI не дублирует поллинг двух разных джобов.
- **Harder:** e2e обязан проверять, что вывод программы реально попал в лог
  (тест `end_to_end_run_mode_streams_program_output`).
- **Given up:** ничего.
- **Migration:** n/a.

## Alternatives considered

- **Поллинг отдельного процесса в GUI:** отвергнуто — дубль кода и пустая
  кнопка (это и был баг).
