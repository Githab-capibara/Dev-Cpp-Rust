# 03. Клонируем формат `.dev` по первоисточнику, а не по памяти

- **Status:** Accepted
- **Date:** 2026-11-23
- **Deciders:** @Githab-capibara
- **Related:** [04. Makefile как в Dev-C++](04-makefile-pipeline.md)

## Context

Файл проекта Dev-C++ 6.x (`*.dev`) — INI-подобный формат с секциями
`[Project]`, `[Version]`, `[Compiler]` и т.д. Спецификация по памяти ненадёжна:
Dev-C++ сам доращивает поля версия за версией, и «примерно похожий» формат
ломал бы открытие чужих проектов — главный сценарий клона.

## Decision

**Читаем оригинальные парсеры/сериализаторы Dev-C++ (`reference/Project.pas`,
`ProjectTypes.pas`) и повторяем формат посимвольно.** Тесты фиксируют
реверсивность: `Project::save` → `Project::load` → точка-в-точку те же поля;
неизвестные ключи не теряются при round-trip.

## Consequences

- **Easier:** проекты настоящего Dev-C++ открываются и собираются в нашем
  клоне без ручной правки; тесты ловят регрессии формата.
- **Harder:** нужна дисциплина при добавлении полей — сперва исходник, потом
  тест.
- **Given up:** ничего.
- **Migration:** n/a.

## Alternatives considered

- **Свой TOML/YAML для проектов:** отвергнуто — ломает совместимость с
  основным сценарием «открыть существующий проект Dev-C++».
- **Читать чужой формат «на глаз» по примерам:** отвергнуто — ненадёжно.
