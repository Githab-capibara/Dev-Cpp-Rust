# 11. Undo/Redo — свои snapshot'ы буфера

- **Status:** Accepted
- **Date:** 2026-11-24
- **Deciders:** @Githab-capibara
- **Related:** [09. Комплишн](09-completion-popover.md), [06. Гейт качества](06-quality-gates.md)

## Context

Dev-C++ умеет Ctrl+Z / Shift+Ctrl+Z в редакторе, это базовая функция
редактора. `GtkSourceView` 5 **удалил публичный undo API**: в
`sourceview5-0.11.3` нет `emit_undo`/`emit_redo`, остаётся только свойство
`enable-undo` и «стандартные акселераторы undo/redo», которые работают лишь
когда GTK сам управляет буфером — а буфер у нас общий с виджетом и живёт под
`Rc`.

Отдельная проблема: на Wayland многие тулкиты отдают набранные символы как
text-commit без key-события. Проверено на живом прогоне: контроллер клавиш
видел `Ctrl+Z`, но **не видел печатных клавиш** — snapshot по keystroke'у
никогда бы не наполнился.

## Decision

**Свой стек snapshot'ов в `Editor`:** `undo_history`/`redo_history` хранят
полный текст буфера (лимит 512), `last_sample` + `batch_open` организуют
батч: первое изменение после 500 мс тишины открывает батч и пишет состояние
*до* него, таймаут закрывает батч и пишет новое состояние в `last_sample`.
Источник правды — `buffer.changed`, а не клавиши.

`Ctrl+Z`/`Ctrl+Y`/`Shift+Ctrl+Z` ловит контроллер клавиш на `view`
(`install_undo`) и вызывает `Editor::undo`/`redo`; действия меню
`win.undo`/`win.redo` и буфер обмена (`cut`/`paste` делают
`snapshot_undo` вручную) используют те же методы. Восстановление — замена
всего текста буфера (`replace_text`), курсор встаёт в начало; полная
история вида «где был курсор» сознательно не моделируется.

## Consequences

- **Easier:** undo/redo не зависит от Input Method'ов и способа ввода
  (клавиатура, `wtype`, вставка из буфера, комплишн) — всё идёт через
  `changed`; поведение идентично на X11 и Wayland.
- **Harder:** храним текст, а не диапазоны правок — на очень больших файлах
  snapshot дороже; 512 снимков × файл компромисс между глубиной и памятью.
- **Given up:** курсор и выделение не восстанавливаются после undo.
- **Migration:** n/a (новый код, старого undo API не было).

## Alternatives considered

- **`enable-undo` + стандартные акселераторы:** отвергнуто — undo живёт
  внутри `GtkSourceView`, мы не можем снять/положить состояние (например,
  после `replace_text` или загрузки файла) и не можем разрулить конфликт с
  нашим буфером.
- **Snapshot по keystroke'у:** отвергнуто — на Wayland печатные символы не
  приходят как key events (проверено `wtype`), стек остался бы пустым.
- **Командный стек (insert/delete с диапазонами):** отвергнуто — требует
  перехватывать каждую мутацию и разбирать IME/compose; избыточно для IDE,
  где undo почти всегда «шаг назад по тексту».
