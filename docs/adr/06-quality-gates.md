# 06. Гейт качества: fmt + clippy `-D warnings` + e2e на реальном компиляторе

- **Status:** Accepted
- **Date:** 2026-11-23
- **Deciders:** @Githab-capibara
- **Related:** [02. Core без GUI](02-core-without-gui.md)

## Context

Требование заказчика: «реально качественная программа», проверяемая линтерами
и реальными прогонами. Экономия времени на ревью не должна приходить за
счёт шума: `clippy::pedantic`/`nursery` дают 100+ замечаний на легаси-код, и
честный `-D warnings` перестаёт быть гейтом.

## Decision

**Политика линтинга:**
- workspace-lints: `rust.missing_docs=warn`, `clippy.all=warn`, `clippy.cargo=warn`;
- `pedantic`/`nursery` — отдельный opt-in профиль (`-W clippy::pedantic`), не
  требуется для зелёного гейта;
- `cargo clippy --workspace --all-targets -- -D warnings` обязан быть чистым.

**Тесты:** юнит-тесты core (в т.ч. реальные компиляции `hello.c` через gcc и
парсинг ошибок) + e2e («создать из шаблона → собрать → запустить →
проверить stdout»). e2e реально зовёт `make`/`g++` — они есть на целевой
машине, гейт это учитывает.

## Consequences

- **Easier:** быстрый детерминированный гейт; документация API обязательна
  (`missing_docs`); CLI быстро показывает состояние инструментов.
- **Harder:** незначительные замечания pedantic придётся править вручную при
  желании строгости; e2e зависит от наличия gcc/g++/make (документировано).
- **Given up:** pedantic как обязательный гейт.
- **Migration:** n/a.

## Alternatives considered

- **Включить pedantic сразу:** отвергнуто — 100+ замечаний «в лоб», включая
  вкусовые; гейт перестаёт быть информативным.
