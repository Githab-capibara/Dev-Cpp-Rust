# 10. Лицензируем devcpp под MIT OR Apache-2.0

- **Status:** Accepted
- **Date:** 2026-11-24
- **Deciders:** @Githab-capibara
- **Related:** [07. Источники Dev-C++ вне репозитория](07-reference-sources.md)

## Context

Клон Dev-C++ не может наследовать GPL: в репозитории нет upstream-кода (см.
ADR-07), весь код написан с нуля, а воспроизведённые по поведению форматы и
шаблоны лицензионно разделяют судьбу нашей реализации. Нужен выбор, который не
мешает использовать devcpp в проприетарных проектах, но остаётся привычным для
Rust-экосистемы.

## Decision

**Двойная лицензия MIT OR Apache-2.0**, стандартная для Rust-проектов:

- в дереве лежат оба текста — `LICENSE-MIT` и `LICENSE-APACHE`;
- заголовки исходников не требуют per-file уведомлений, лицензия указана в
  `Cargo.toml` каждого крейта (`license = "MIT OR Apache-2.0"`);
- атрибуция оригинального Dev-C++ дана в README как текст, без переноса кода.

## Consequences

- **Easier:** максимальная совместимость с экосистемой crates.io; GPL-споры не
  касаются пользователей devcpp.
- **Harder:** нужно поддерживать два текста лицензий синхронно при правках.
- **Given up:** ничего.
- **Migration:** n/a.

## Alternatives considered

- **Только GPL-2.0 (как Dev-C++):** отвергнуто — клон — отдельная кодовая
  база, копилефт upstream нас не связывает, а урезанная переиспользуемость
  мешает пользователям.
- **Только MIT:** отвергнуто — теряем защиту патентных грантов, которую даёт
  Apache-2.0.
